# ADR 003 Fronteira Python com funcionamento degradado

Data: 27 de outubro de 2026. Estado: implementado no mini lab.

## Contexto e requisitos

RF03 recomendação inteligente e RF04 assistente educacional acrescentam capacidades Python ao Core Java. O laboratório valida a fronteira e a indisponibilidade; não treina ML nem chama um LLM externo.

RNFs analisados: deploy independente, escalabilidade, tolerância a falhas, interoperabilidade, desempenho e manutenibilidade. ASRs selecionados: D3 A1 tolerância a falhas limita o tempo de espera e exige fallback; D3 A2 deploy independente exige processo com ciclo próprio sem reiniciar o Core; D3 A3 interoperabilidade exige contrato HTTP/JSON entre Java e Python.

RPCs: Core em Java/Spring Boot; ML/RAG em Python; falha da IA não bloqueia fluxo essencial.

## Alternativas

| Alternativa | Benefícios | Custos e limites |
| --- | --- | --- |
| IA embutida no Core | Menos processos e chamadas | Integração entre runtimes e falhas acopladas; dificulta ciclo Python próprio |
| Módulo Python acoplado ao mesmo ciclo | Reuso local de organização | Continua acoplando implantação e disponibilidade; Python por si só não define autonomia |
| Serviço Python separado | Contrato independente e reinício sem parar Core | Rede, serialização, timeout, fallback e monitoração adicionais |

## Decisão e consequências

Usar FastAPI em processo separado, consumido por HttpClient do Java. A requisição tem limite de 600 ms e conexão de 300 ms; falha de conexão, HTTP não 200 ou resposta inválida retorna catálogo geral e mensagem de indisponibilidade, marcando `degradado=true`. Esses limites são parâmetros do laboratório, não SLA fornecido pelo enunciado. Cursos, matrícula e Ranking não chamam IA como pré-condição.

Recomendação e assistente ficam juntos na primeira fronteira Python porque compartilham runtime e ainda não há evidência de cargas/ciclos incompatíveis. Separá-los dependerá de métricas, dados e requisitos próprios. Não se introduz um banco vetorial sem evidência de necessidade.

A recomendação usa catálogo fixo identificado como simulação. O assistente demonstra recuperação lexical de três materiais locais, informa fontes e `modo=sem-LLM`; não é uma implementação completa de RAG com geração por LLM. A fronteira está preparada para implementar essas capacidades posteriormente sem alterar os fluxos essenciais do Core.

Para reduzir infraestrutura do mini lab, o mesmo processo FastAPI hospeda o consumidor de notificação de teste do D4; isso é compartilhamento de laboratório, não afirmação de que IA e notificações formam o mesmo domínio em produção.

## Evidência e revisão

`docs/evidencias/desafio3/experimento.json` registra resposta com Python ativo, interrupção real do processo, fallback e consulta de cursos com sucesso. O processo Python é reiniciado sem reiniciar o Core. Testes Java cobrem sucesso, conexão recusada e HTTP 503. Testes Python verificam que a simulação e as fontes são explicitamente identificadas.

Reavaliar fronteiras ML/RAG quando houver perfil de carga e frequência de atualização distintos. Seleção de modelo, corpus real e fornecedor de LLM são decisões de uma implementação de produto, fora da hipótese deste mini lab.
